# CRM

Внутренняя CRM: заявки (Kanban), клиенты, задачи, дашборд с графиками, управление сотрудниками.
Стек: Next.js 16 (App Router) · TypeScript · Tailwind CSS 4 · Turso (libSQL) · JWT в httpOnly-cookie · @dnd-kit · recharts.

## Быстрый старт (локально)

```bash
npm install
cp .env.example .env.local   # заполните JWT_SECRET и ADMIN_PASSWORD
npm run seed:admin           # создаст таблицы и первого администратора
npm run seed:demo            # необязательно: демо-менеджеры, клиенты, заявки, задачи
npm run dev                  # http://localhost:3000
```

Локально база — файл `local.db` (`TURSO_DATABASE_URL=file:local.db`), Turso-аккаунт не нужен.

| Команда | Что делает |

| `npm run build` / `npm start` | продакшен-сборка и запуск |

| `npm test` | автотесты (vitest): вход и лимиты, смена пароля, права доступа, proxy |
| `npm run db:migrate` | применить схему (идемпотентно, `create table if not exists`) |

## CI (GitHub Actions)

При каждом push и pull request в `main` workflow [`.github/workflows/ci.yml`](.github/workflows/ci.yml) на чистой Ubuntu (Node 24) выполняет `npm ci`, `npm run typecheck`, `npm test` и `npm run build`. Секреты не нужны: используются заглушки. Результат — во вкладке **Actions** репозитория на GitHub (и галочка/крестик у коммита).

## Деплой на Vercel + Turso

Продакшен: https://crm-ramazon.vercel.app — проект Vercel `crm-ramazon`, подключён к GitHub-репозиторию `rkomp9802-prog/crm-ramazon`.

**Автодеплой:** каждый `git push` в `main` сам собирает и выкладывает продакшен. Push в другие ветки получает отдельный preview-адрес, но переменные базы заданы только для Production — на preview вход работать не будет (так задумано, чтобы preview не писал в боевую базу; для preview заведите отдельную базу Turso).

Первичная настройка (уже сделана):
1. `turso db create …` → `turso db show … --url` и `turso db tokens create …`, значения — в `.env.local`.
2. `npm run seed:admin` — создаст схему и первого администратора в Turso.
3. В проекте Vercel заданы `TURSO_DATABASE_URL`, `TURSO_AUTH_TOKEN`, `JWT_SECRET` (свой, не как в `.env.local`) и `APP_TIMEZONE` — для Production.
4. `vercel.json` задаёт фреймворк `nextjs`; `.vercelignore` не даёт загрузить на Vercel секреты и локальную базу.

Ручной деплой без GitHub (PowerShell): `npx.cmd vercel@64.7.0 deploy --prod`. Версия 64 — последняя на чистом JavaScript: более новые версии CLI при первом запуске докачивают свой исполняемый файл.

## Telegram-бот

Клиент пишет боту — в CRM появляется заявка (источник `telegram_bot`, статус «новая», без ответственного) и клиент с его `telegram_id`. Повторное сообщение того же человека создаёт новую заявку на того же клиента. У Telegram-клиента нет телефона: поле пустое, в интерфейсе показывается «—». Боту отвечает «Спасибо, ваша заявка принята…»; ошибка отправки ответа заявку не отменяет.

Переменные (локально — `.env.local`, на Vercel — Production):
- `TELEGRAM_BOT_TOKEN` — токен от @BotFather;
- `TELEGRAM_WEBHOOK_SECRET` — случайная строка, например `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`. Без неё вебхук отвечает 401.

Регистрация вебхука (после деплоя; значения подставьте из своих переменных, не публикуйте их):

```powershell
curl.exe -sS "https://api.telegram.org/bot$env:TELEGRAM_BOT_TOKEN/setWebhook" `
  -d "url=https://crm-ramazon.vercel.app/api/telegram/webhook" `
  -d "secret_token=$env:TELEGRAM_WEBHOOK_SECRET"
```

Проверка: `getWebhookInfo` с тем же токеном — поле `last_error_message` должно быть пустым.

## Роли

- **admin** — все заявки, клиенты, задачи; управление сотрудниками; полная аналитика с разбивкой по сотрудникам.
- **manager** — только свои заявки и задачи (назначенные на него); может создавать клиентов и заявки; аналитика только по себе.

Права проверяются в каждом API route (`lib/http.ts` → `requireApiUser`, `assertAdmin`), а не только скрытием кнопок.
`proxy.ts` (в Next.js 16 так называется бывший `middleware.ts`) делает быструю проверку подписи JWT и закрывает `/users` для не-админов.

## Отличия от спецификации

- `proxy.ts` вместо `middleware.ts` — переименование в Next.js 16.
- Роль и активность пользователя на каждом запросе берутся из БД, а не из JWT: деактивированный сотрудник теряет доступ сразу, а не через 7 дней.
- Служебные колонки: `clients.search` (поиск по кириллице без учёта регистра — `LIKE` в SQLite этого не умеет), `leads.closed_at` (для «среднего времени закрытия»), `users.must_change_password` и `users.session_version`, плюс таблица `login_attempts` — см. «Безопасность входа».
- Страницы приложения лежат в группе маршрутов `app/(crm)/…` — общий layout с меню; URL такие же, как в спецификации.
- Изменяющие запросы к API с чужого `Origin` отклоняются (защита от CSRF).

## Безопасность входа

- **Лимит попыток** (`lib/rate-limit.ts`, счётчики в таблице `login_attempts`): за 15 минут — не больше 5 ошибок с одного IP на один email, 25 — с одного IP на любые email, 30 — на один email с любых IP. Дальше вход блокируется на 15 минут (ответ 429). Счётчики хранятся в БД, а не в памяти: на Vercel у каждого экземпляра функции своя память.
- **Временный пароль.** Пароль, который задал администратор (новый сотрудник или сброс), — временный. Пока сотрудник не сменит его на странице `/password`, разделы CRM и API ему недоступны.
- **Смена пароля** — кнопка «Пароль» в шапке. Нужно ввести текущий пароль (не больше 5 ошибок за 15 минут).
- **Отзыв сеансов.** Смена или сброс пароля увеличивает `users.session_version` — все ранее выданные cookie перестают работать.
- Попытка засчитывается **до** проверки пароля, поэтому пачка параллельных запросов не обходит лимит; успешный вход снимается со счётчиков.
- IP берётся из `x-real-ip` / `x-forwarded-for`. На Vercel их выставляет платформа; без доверенного прокси заголовок можно подделать — тогда остаётся лимит по email. Если IP нет совсем, лимиты по IP не применяются (иначе все сотрудники делили бы один счётчик).
- Лимит по email — компромисс: зная email сотрудника, можно на 15 минут заблокировать ему вход 30 неверными попытками.

Схема БД применяется автоматически при первом обращении приложения к базе (`ensureSchema` в `lib/schema.ts`), поэтому после обновления кода приложение не упадёт на старой базе. `npm run db:migrate` можно запускать и вручную — команда идемпотентна.

## Осознанные упрощения (MVP)

- Нет истории изменений заявки — только текущее состояние и свободные заметки.
- Нет email/Telegram-напоминаний — только подсветка просроченных задач и счётчик в меню.
- Нет восстановления пароля по email — забытый пароль сбрасывает администратор.
- Интеграции с формой сайта и Telegram-ботом (раздел 13 спецификации) не реализованы; точка входа — `lib/leads.ts` → `createLead`.
